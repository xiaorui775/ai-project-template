# ADR-0001 后端使用 Maven 多模块而非独立仓库

- 状态：已采纳
- 日期：2026-09-02
- 决策人：@backend-lead

## 背景

团队 8 人，服务 5 个。原本每个服务一个 Git 仓库，公共代码（Result、异常处理、脱敏）靠复制粘贴，改一次要改 5 处。同时前端也需要与后端同频发布。

## 可选方案

A. 每服务独立仓库 + 公共库私服发布
B. 单仓库 + Maven 多模块聚合（前后端同仓）
C. 单仓库 + 只前端合并，后端仍独立

## 决策

选 **B**。

## 理由

- 公共改动一次提交同时生效，原生支持"原子 PR"（改 common + 改调用方一起评审）。
- 团队规模下不需要独立发布节奏；5 个服务同版本发布反而简单。
- CI 用 `-pl <module> -am` 增量构建，性能可接受。
- 私有库发布流程（版本号、兼容性）对 8 人团队是纯负担。

## 后果

- 正面：公共代码不再漂移；一次 PR 可跨服务改契约。
- 负面：仓库变大（克隆 40s+）；CI 若不写 `-pl -am` 会全量构建。
- 后续：若某个服务需要独立发布节奏（如对外开放 SDK），再单独拆出去，并新写 ADR。
