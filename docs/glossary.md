# 领域术语表

> 作用：减少 AI 对业务名词的误读。出现"这个字段到底是什么意思"时，先查这里。
> 规则：新增名词由提出人补充；术语与代码标识符要能对应上。

| 术语 | 代码标识 | 含义 | 易混淆点 |
|---|---|---|---|
| 租户 | `tenantId` | 一个签约客户，数据完全隔离 | 不是"部门" |
| 组织 | `orgId` | 租户内的组织单位，树形 | 与 `tenantId` 不同层级 |
| SPU | `spuId` | 标准商品单元（同一商品的不同规格共享 SPU） | 与 SKU 不是 1:1 |
| SKU | `skuId` | 最小可售单元，有独立库存与价格 | 库存只记在 SKU 上 |
| 订单 | `orderNo`（展示）/ `id`（主键） | 用户一次提交生成的单据 | 对外用 `orderNo`，内部关联用 `id` |
| 业务单号 | `bizNo` | 客户端生成的幂等键，唯一索引 | 不是订单号 |
| 已开票 | `invoiceStatus=ISSUED` | 发票已提交税务系统并成功 | 与"已支付"是两件事 |
| 结算 | `settlement` | 平台向商户打款的流程 | 与"支付"（用户付钱）相反方向 |
| 快照 | `snapshot` | 下单时固化的价格/名称 | 不要用商品当前值展示历史订单 |
| 灰度 | `gray` | 按比例/白名单放量的发布方式 | 不是"测试环境" |
