# PRD —— 产品需求文档（模板 + 示例）

> 作用：把"要做什么、做到什么程度算完成、什么不做"固化成文字，防止 AI 猜需求。
> 规则：一个大需求一个文件，放 `docs/requirements/<需求编号>-<slug>.md`，本文件是模板与示例。

## 示例：需求 REQ-001 发票批量下载

### 1. 背景

财务同事每月需手工逐张下载 30–200 张发票，耗时约 2 小时，且容易漏下载。

### 2. 目标（可度量）

- 财务角色能在列表页一次勾选并下载全部发票，100 张耗时 < 30s。
- 下载失败时能明确知道哪几张失败。

### 3. 用户角色与场景

| 角色 | 场景 | 期望 |
|---|---|---|
| 财务 | 月末集中下载 | 一次勾选，得到一个 ZIP |
| 财务主管 | 抽查 | 能按月份/金额筛选 |

### 4. 验收标准（Given / When / Then）

```
AC-1 正常下载
Given 用户已登录，角色为 FINANCE
And 在发票列表勾选了 3 张已开票状态的发票
When 点击「批量下载」
Then 浏览器下载文件 invoices-20261117.zip，内含 3 个 PDF，文件名包含发票号

AC-2 超过上限
Given 勾选了 51 张发票
When 点击「批量下载」
Then 提示「单次最多下载 50 张，请分批处理」，且不发起请求

AC-3 部分失败
Given 其中 1 张发票的 PDF 文件在 OSS 已丢失
When 点击「批量下载」
Then ZIP 内包含 2 个正常 PDF + `_failed.txt`（列出丢失的发票号与原因）

AC-4 无权限
Given 用户角色为普通员工
When 调用下载接口
Then 返回 403 + 错误码 20403「无权限」
```

### 5. 明确不做（Scope Out）

- ❌ 不做异步任务队列（> 50 张由用户分批）
- ❌ 不做邮件发送
- ❌ 不新增发票状态

### 6. 接口变更

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/invoices/batch-download` | body: `{ ids: string[] }`，返回 `application/zip` |

详见 `docs/api/invoice.md`。

### 7. 数据与权限

- 新增权限点：`invoice:download`（写入 `Permission` 枚举）
- 数据范围：仅本人所属租户的发票（`tenant_id` 校验）

### 8. 非功能要求

- P95 < 8s（50 张）；单次内存占用 < 100MB（流式打包，不要先加载全部文件到内存）
- 审计日志：记录操作人、数量、结果

### 9. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| OSS 中文件缺失 | 部分失败 | AC-3 已覆盖 |
| 一次性 ZIP 包过大 | OOM | 流式写 `ZipOutputStream` |

### 10. 上线计划

- 灰度：先开放财务组（Nacos 开关 `invoice.batch-download.enabled`）
- 回滚：关闭开关即回到单个下载
